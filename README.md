## Контакты

По вопросам сотрудничества, предложений и любым другим вопросам — [@I_Love_Norway](https://t.me/I_Love_Norway) в Telegram.

---

Сервис для пополнения словарного запаса английского языка. Пользователь проходит
короткую сессию: сервер выдаёт очередь карточек (просроченные повторения плюс
несколько новых слов), проверяет ответы и пересчитывает интервалы повторения.

Сервис рассчитан на нескольких пользователей и строится вокруг одной идеи:
**слова запоминаются не от просмотра, а от попытки вспомнить**. Поэтому здесь есть
проверка ответа, оценка и алгоритм интервальных повторений, а не лента слов.

## Что уже работает

* Регистрация и вход, токен доступа, изоляция данных пользователей. Ник уникален —
  по нему пользователи находят друг друга.
* **Тренажёр в браузере**: пять разделов — тренировка, избранное, друзья, настройки, профиль.
  Отдельной сборки фронтенда нет: статические файлы и ES-модули отдаёт сам API.
* **Мини-апп в Telegram**: тот же интерфейс, открытый из чата с ботом. Внутри Telegram
  работает вход без пароля — по подписи `initData`, которую сервер проверяет токеном бота.
  Если Telegram ещё не привязан, мини-апп предлагает привязать его по коду прямо из себя.
* **Бот в Telegram**: слово дня, сводка по команде `/today`, напоминание в выбранное
  пользователем время и кнопка запуска мини-аппа. Привязка аккаунта — по одноразовому коду.
* **Аватар**: загрузка JPEG, PNG или WebP до 2 МиБ и удаление. Формат проверяется
  по содержимому файла, а не по имени: каталог аватаров отдаётся статикой.
* **Тёмная тема**: светлая, тёмная и «как в системе». Внутри Telegram палитра берётся
  у клиента, поэтому мини-апп совпадает с оформлением мессенджера.
* **Избранные слова**: отметка звёздочкой в словаре колоды или прямо в карточке.
  Избранные идут первыми в очереди повторений и доступны отдельной тренировкой вне расписания.
* **Аудирование**: упражнение «на слух» озвучивается браузером через Web Speech API —
  ни файлов, ни зависимостей. Слово произносится, а не показывается; кнопка
  «Медленнее» и повторное прослушивание доступны на разборе ответа.
* **Свои слова и колоды**: личная колода создаётся в интерфейсе, слова в неё
  добавляются новые или берутся из словаря поиском. Тренируется она теми же
  механизмами, что и системная: сессия, расписание, статистика, достижения.
* **Достижения и цели**: пятнадцать наград — «Первый шаг», «Сотня», «Неделя без пропусков»,
  «Колода пройдена», «Пять тысяч ответов» и другие. У каждого достижения своя
  иконка. Прогресс считается из накопленных данных, а не хранится
  отдельно, поэтому награда не может разойтись с настоящим прогрессом. Рядом
  с полным списком показывается **ближайшая незакрытая цель** — то, ради чего
  стоит зайти завтра.
* **Страницы прогресса**: плитки «Выучено», «В работе» и «Пора повторить»
  открывают списки слов с озвучкой, транскрипцией и сроком повторения.
  По нажатию на слово открывается карточка с переводами и примерами;
  на странице повторений сверху есть кнопка запуска тренировки.
* **Друзья по нику**: поиск, заявка, принятие и отклонение, прогресс друг друга
  (выучено слов, серия дней, ответы за сегодня). Встречная заявка оформляет дружбу сразу.
  Из списка друзей и из рейтинга открывается **профиль игрока**: его слова, серия,
  ответы за всё время и за последнюю неделю. Чужой профиль доступен только другу.
* **Рейтинг недели среди друзей**: последние семь дней, порядок — слова за неделю,
  затем ответы, затем серия дней. Считается в часовом поясе каждого участника,
  поэтому у друзей из разных поясов «неделя» своя.
* **Кнопка «Не знаю»**: показывает ответ, не заставляя угадывать, и честно ставит оценку «забыл».
* **Восстановление доступа**: вход по email или нику, сброс пароля по одноразовой
  ссылке в письме и команда `reset-password` для сброса вручную. Почтовый провайдер
  задаётся настройками; без него письмо выводится в журнал сервера, и форма «забыли
  пароль» честно об этом предупреждает.
* Словарь из 18 тематических колод: **438 слов**, 597 переводов, 978 примеров
  с переводом на русский и транскрипцией IPA. Колоды подобраны под бытовые
  и бюрократические задачи: первые дни, жильё, работа, медицина, банк и документы,
  быт и школа, путешествия, офис и IT, эмоции, погода, учёба, телефон и интернет, small talk.
* Сессия обучения: очередь сохраняется в базе, поэтому обновление страницы
  или переход на другое устройство не меняет набор слов. Явно выбранная колода
  не ограничена дневным лимитом новых слов — второй темой можно заняться в тот же день.
* Проверка ответов с нормализацией: регистр, лишние пробелы, диакритика, знаки
  препинания и дефисы не влияют на результат, а опечатка в длинном слове прощается.
* Алгоритм интервалов SM-2 с этапом заучивания; поля под FSRS уже заложены.
* Прогресс: выучено, в работе, серия дней, кривая удержания за 30 дней.
  День идёт в серию, когда выполнена дневная цель.
* Миграции EF Core и идемпотентный импорт словаря.
* **Что нового**: страница с историей выпусков — что исправлено, что появилось
  и в какой версии. Номер версии берётся из сборки (`Directory.Build.props`)
  и показывается рядом, поэтому на странице видно, обновилось ли приложение.
  Открывается из шапки (ссылка с номером версии), из профиля и из подписи под
  списком разделов. В нижнем меню её нет: в мини-аппе панель рассчитана на пять
  разделов, шестой отнял бы место у остальных.
* 264 модульных теста, 56 интеграционных на живой базе и сквозной сценарий
  проверки API из 197 проверок. Всё это выполняется на каждый push в GitHub Actions.

## Архитектура

Зависимости направлены строго внутрь: внешние слои знают о внутренних, но не наоборот.

```
EnglishTrainer.Domain          сущности, правила, интерфейсы. Не зависит ни от чего, кроме BCL.
        ▲
EnglishTrainer.Application     сценарии использования, DTO, порты. Знает только Domain.
        ▲
EnglishTrainer.Infrastructure  EF Core, PostgreSQL, хеширование, токены, импорт словаря, Telegram.
        ▲
EnglishTrainer.Api             HTTP-маршруты, аутентификация, статический интерфейс. Знает всё, но тонкий.
EnglishTrainer.Bot             второй процесс над теми же слоями: опрос Telegram, напоминания.
```

| Проект | Ответственность | Чего в нём нет |
|---|---|---|
| `Domain` | Сущности, перечисления, алгоритм повторений, расписание напоминаний, интерфейсы репозиториев и портов | EF Core, HTTP, SQL, JSON |
| `Application` | Сценарии: сборка сессии, проверка ответа, статистика, аутентификация, привязка Telegram, DTO | Знания о PostgreSQL, о таблицах, о формате токена |
| `Infrastructure` | Реализации портов: `AppDbContext`, репозитории, `IClock`, хешер паролей, JWT, сидер, проверка подписи Telegram, файлы аватаров | Бизнес-правила, HTTP-маршруты |
| `Api` | Маршрутизация, аутентификация, обработка ошибок, отдача интерфейса, запуск | Бизнес-логика: обработчики вызывают сервисы и возвращают результат |
| `Bot` | Опрос Telegram, разбор команд, отправка напоминаний по расписанию | Своих правил обучения: он вызывает те же сервисы Application, что и API |

Практическая проверка разделения: чтобы заменить PostgreSQL на другую базу,
достаточно переписать `Infrastructure`. Чтобы поменять алгоритм повторений —
добавить реализацию `ISrsScheduler` в `Domain`. Файл `Program.cs` при этом не меняется.

Отдельно про бота: он **не ходит в API по HTTP**, а подключает те же слои. Это не
нарушение границ, а их следствие — бот такой же адаптер, как HTTP-слой, и правила
обучения в нём не дублируются. Плата за это — общий секрет подписи токенов и общая
база у двух процессов; выигрыш — один набор сценариев вместо двух.

## Ключевые решения и их причины

### Личная колода — обычная колода с владельцем

Отдельной сущности нет намеренно. Прогресс уже привязан к паре «пользователь +
слово», а не к колоде, поэтому личная колода работает всеми теми же механизмами —
сессией, расписанием, статистикой, достижениями — и ни одного нового не требует.
Добавилось одно поле: `decks.owner_id`, необязательное, потому что у системных
колод владельца нет, и «системная колода принадлежит кому-то» было бы неправдой.

Слова живут в общем справочнике. Добавив «landscape» в свою колоду, человек
не создаёт второе слово, а связывает существующее: слова с одинаковым написанием
и частью речи переиспользуются. Иначе одно и то же слово училось бы дважды
независимо, и статистика стала бы неправдой — ровно та причина, по которой
прогресс и привязан к слову, а не к карточке колоды.

По той же причине своё слово **не правит общие значения**: если слово уже есть
в словаре, оно берётся как есть. Правка от имени одного человека меняла бы
упражнения всем остальным — чужая неверная формулировка стала бы засчитываться
как правильный ответ, потому что проверка принимает любой из переводов слова.

Чужая и системная колода отвечают **404, а не 403**. Разница существенна: 403
подтверждает, что колода существует, и перебором адресов можно выяснить, какие
личные колоды есть у других людей. Отказ «не найдено» не сообщает ничего.
Правило живёт в сущности (`Deck.IsEditableBy`), а не в сервисе: проверка нужна
и удалению колоды, и добавлению слова, и удалению слова — три места, в которых
легко забыть одно и тем самым открыть дыру.

Адрес личной колоды — случайный (`own-49cdcf78`), а не транслитерация названия.
Названия люди пишут по-русски, и «Моя колода» превратилось бы в «moya-koloda» —
с таблицей транслитерации, разбором коллизий и всё равно непредсказуемым
результатом. Адрес виден только в запросах, а человек работает с названием.

### У одного числа — одно определение

Интеграционные тесты нашли расхождение, которое до них никто не замечал: «выучено»
считалось в двух местах по-разному. В сводке прогресса — как «срок повторения дальше
чем через месяц», в прогрессе колоды — как «интервал не меньше 30 дней». На границе
(интервал ровно 30 дней, повторение сегодня) карточка попадала в выученные в колоде
и не попадала в сводку: два экрана показывали разные числа об одном и том же.

Теперь определение одно — `CardState.LearnedIntervalDays`, и оно же используется
в `CardState.IsLearned`, в сводке, в прогрессе колоды и в достижении «Колода
пройдена». Тест `GetSummaryAsync_AgreesWithCardStateIsLearned` берёт интервалы
по обе стороны порога, включая ровно порог, и требует, чтобы сводка совпала
с правилом сущности. Если определение снова разъедется, тест это поймает —
а не пользователь, увидевший две разные цифры на двух экранах.

### Рейтинг идёт по скользящему окну, а не по календарной неделе

Календарная неделя требует общего для всех начала отсчёта, а участники живут
в разных часовых поясах: у одного понедельник уже начался, у другого ещё
воскресенье. Скользящее окно в семь дней честнее и, кроме того, не обнуляет
результат в понедельник утром — падение в ноль после недели работы демотивирует
сильнее, чем отсутствие рейтинга.

Порядок ключей сортировки — от самого дорогого показателя к самому дешёвому:
слова за неделю, затем ответы, затем серия дней. Сто ответов можно набрать
за вечер, а сто новых слов требуют недели. Последний ключ — ник: без него
порядок участников с одинаковым счётом зависел бы от порядка строк в базе,
и список прыгал бы при каждом обновлении страницы. При равенстве счёта места
не разделяются (1, 2, 2, 4): придумывать разрыв между одинаковыми результатами —
значит наказывать за то, чего человек не делал.

Рейтинг строится по уже собранной дневной статистике, а не по отдельным счётчикам
для соревнования. Причина та же, что и у достижений: два источника одного числа
расходятся, и «у меня больше ответов, а я ниже» подрывает доверие ко всему экрану.
Соревнование идёт только среди друзей: рейтинг среди незнакомых людей наказывает
новичка за то, что он новичок, и мотивирует ровно наоборот задуманному.

### Прогресс достижений не хранится, а хранится только факт награды

Соблазн завести счётчики («сколько слов выучено») и обновлять их вместе
с наградой велик, но у двух источников одного числа есть неприятное свойство:
они расходятся. Человек увидел бы «100 из 100» рядом с закрытой плашкой и решил,
что приложение сломалось. Поэтому в `user_achievements` лежит только код награды
и её дата, а прогресс считается из состояний карточек, дневной статистики
и журнала ответов — ровно из того, из чего считается весь остальной прогресс.

Проверка порогов идёт при чтении достижений, а не после каждого ответа. Это
компромисс: награда подсвечивается на несколько секунд позже, чем заработана,
зато самый горячий путь приложения — ответ на карточку — не обрастает ещё тремя
запросами к базе. Страница тренировки запрашивает достижения при каждой отрисовке,
поэтому после законченной сессии награда появляется сразу.

Считаются только те показатели, которые нужны ещё не полученным достижениям.
Когда у человека закрыты «сотня слов» и «тысяча ответов», соответствующие
счётчики уже никто не спрашивает — и запросов к базе не делается. Список
достижений задан кодом, а не таблицей: достижение — это правило, а правило,
лежащее в данных, нельзя ни отревьюить, ни покрыть тестом.

### «Семь дней подряд» считается по лучшей серии, а не по текущей

Награда, которую можно потерять, перестаёт мотивировать и начинает пугать.
Один пропущенный день не должен отбирать «Неделю без пропусков» — достижение
фиксирует, что человек это уже сделал. По той же причине дата получения
хранится: «получено 3 марта» — то, чем хочется поделиться, а галочка без даты —
просто галочка.

### Упражнение «на слух» озвучивает браузер, а не сервер

Записей слов в словаре нет и не будет: аудио Wikimedia требует атрибуции, а
собственная озвучка 438 слов — это отдельный проект. Поэтому произносит слово
браузер через Web Speech API (`js/speech.js`): бесплатно, без файлов, без сети
и без единой зависимости. До этого упражнение «на слух» было мёртвым — сервер
честно откатывал его к вводу, потому что проигрывать было нечего.

Побочный эффект, который стоит знать: текст для произношения обязан быть
на клиенте, а этот текст и есть правильный ответ. То есть в упражнении на слух
карточка **содержит ответ** — единственный такой случай. Правило «карточка
не содержит ответа» при этом не нарушено по существу: оно защищало от того,
что ответ виден на экране до попытки, а здесь его на экране нет — клиент
произносит текст и не рисует его. Упражнения на ввод и написание ответа
не содержат ни в одном поле, и это закреплено и юнит-тестом, и сквозной проверкой.

Браузер без синтеза речи не остаётся без задания: страница показывает перевод
и превращает карточку в написание по переводу, а принимается всё то же
английское слово — оценка от способа показа не зависит.

### Прогресс привязан к паре «пользователь + слово», а не к карточке в колоде

Одно слово может входить в несколько колод (`rent` есть и в «Жилье», и в «Быте»).
Если хранить состояние по карточке колоды, пользователь будет «учить» одно слово
несколько раз независимо, а статистика станет неправдой. Состояние — это
`CardStates (UserId, WordId)` с уникальным индексом на пару. Импорт словаря это
подтвердил: из 156 связей «слово в колоде» уникальных слов оказалось 145.

### Карточка не содержит правильного ответа

`StudyCardDto` отдаёт `Prompt` — то, что нужно прочитать (английское слово для выбора
варианта, перевод для ввода), — но не само искомое слово. Проверка происходит
на сервере. Если бы ответ лежал в карточке, в заданиях на ввод он был бы виден
на экране, и упражнение теряло бы смысл. Правило закреплено тестом
`StudyCardMappingTests.CardForTypingExercise_DoesNotContainTheAnswer`.

### Очередь сессии хранится в базе, а не собирается на каждый запрос

Иначе при обновлении страницы пользователь получал бы другой набор слов,
а «прерванная» сессия терялась бы. Одна активная сессия на пользователя
гарантируется частичным уникальным индексом `ix_study_sessions_active_per_user`,
а не проверкой в коде: проверка не спасает от гонки двух одновременных запросов.

### Сейчас SM-2, позже FSRS

FSRS точнее, но требует весов, обученных на большой истории ответов которой
у нового проекта нет. Поэтому работает SM-2, а данные под будущий переход уже
собираются: в `CardStates` есть `Stability` и `Difficulty`, а `ReviewLogs`
хранит состояние карточки **до** каждого ответа, поэтому историю можно пересчитать
задним числом. Журнал пишется всегда — без него переход на FSRS будет невозможен.

### Лимит новых слов — защита от выгорания, а не ограничение

По умолчанию 10 новых слов в день. Пользователь, взявший 50, через три дня получает
около 150 карточек к повторению и уходит навсегда. Лимит настраивается, но имеет
жёсткие границы (0–100), и выход за них — ошибка валидации.

### День идёт в серию только при выполненной дневной цели

Раньше серия продлевалась за любой ответ: человек с дневной целью в тридцать ответов
видел «серия 1» после двадцати, и цифра расходилась с тем, что он сам себе назначил.
Теперь день занятий — это выполненная цель, а не факт захода в приложение.
По умолчанию цель — **десять ответов**, ровно одна обычная сессия: столько же новых
слов даётся в день. Цель выше дневного лимита означала бы, что серию нельзя продлить
в первый же день, и человек видел бы «0 дней» после честно пройденной сессии.

Цель хранится **в дневной записи** (`daily_stats.daily_goal`), а не берётся из
настроек при подсчёте. Поэтому повышение плана не обнуляет уже набранную серию:
подняв цель с 20 до 30, человек не теряет двадцать дней подряд — прошлые дни
остаются такими, какими были выполнены. Сегодняшний день — исключение: он ещё идёт,
и правка цели применяется к нему сразу, чтобы «снизил планку до сделанного» работало
без лишнего ответа. У записей, созданных до появления столбца, цель равна нулю —
«не зафиксирована»: такой день засчитывается при любом ответе, как и раньше,
и миграция никому не обрывает серию задним числом.

### Лимит новых слов останавливает автоподбор, но не выбор человека

Лимит ограничивает то, что приложение берёт на себя: общая тренировка не подмешивает
новые слова сверх остатка на день. Но если человек открыл конкретную колоду, он
попросил именно её — и упереться в «повторять нечего» после первого прогона по другой
теме выглядело поломкой, потому что колода была нетронута.

Поэтому явно выбранная колода лимитом не ограничивается, но и целая колода за один
заход не выдаётся: вводится обычная дневная норма (`newWordsPerDay`) — иначе выбор
темы означал бы «получить все её слова сразу», то самое выгорание, от которого лимит
и защищает. Введённые слова честно попадают в дневную статистику, так что общая
тренировка в тот же день новых слов уже не предложит.

Без выбранной колоды общая тренировка ищет новые слова сразу во всех колодах,
а не только в первой системной. Раньше после прохождения «Первых дней» новые
слова переставали приходить, хотя в других колодах их было ещё много.

### Выбранная колода ограничивает и повторения

`StudySession.DeckId` долго записывался, но ни на что не влиял: запрос «заниматься
колодой B» приносил слова колоды A, потому что долг по повторениям общий для
пользователя. Теперь при выбранной колоде очередь строится только из её слов
(через `deck_words`: слово может лежать в нескольких колодах, и «колода карточки» —
свойство связи, а не карточки). Активная сессия другой колоды при этом закрывается,
а не подменяет запрошенную: две очереди одновременно держать нельзя, а прогресс
хранится в состояниях карточек и не теряется.

### Знаки препинания не участвуют в проверке, опечатки прощаются отдельно

Сравнение ответа начинается с нормализации (`AnswerNormalizer`): регистр, лишние
пробелы, диакритика латиницы и **все знаки препинания** отбрасываются. Перевод
«Который час?» и ответ «который час» — одно и то же, и требовать вопросительный знак
в поле ввода нельзя. Апостроф и дефис удаляются без пробела («don't» = «dont»,
«well-known» = «wellknown»), а сравнение дополнительно повторяется по строке без
пробелов, поэтому «well known» — тот же ответ.

Опечатка прощается, но осторожно: одна — в слове от пяти букв, две — от девяти,
расстояние считается по Дамерау — Левенштейну (перестановка соседних букв —
одна опечатка), и совпадать должны начало и конец слова. Это не украшение:
русские формы одного слова расходятся в окончании («красный» и «красная»),
а близкие по написанию разные слова — в начале («работа» и «забота»), и без
этих двух признаков тренажёр засчитывал бы другое слово как опечатку.
Зачтённый с опечаткой ответ возвращается отдельным полем `matchedWithTypo`:
балл не отнимается, но эталон показывается, чтобы закрепилось словарное написание.

### Чужой профиль отвечает 404

Профиль игрока открывается из списка друзей и из рейтинга, но только другу.
Постороннему сервер отвечает «не найдено», а не «запрещено»: 403 подтверждал бы,
что такой ник существует, и перебором ников можно было бы выяснить, кто вообще
зарегистрирован. По той же причине в ответе нет ни настроек, ни почты — только
прогресс, ради которого профиль и открывают.

### Почта: SMTP, а без настройки — журнал

Письмо нужно ровно одно — ссылка на сброс пароля. Реализация порта `IEmailSender`
выбирается по настройкам: задан `Email:Smtp:Host` и `Email:From` — письмо уходит
по SMTP, не задан — работает прежний режим с записью в журнал, и форма «забыли
пароль» честно об этом говорит (способ доставки она спрашивает у сервера).

Сбой отправки не остаётся незамеченным: форма получает **502** и текст «письмо
отправить не удалось, проверьте настройки почты», а само письмо целиком уходит
в журнал — доступ можно вернуть даже со сломанной почтой. Раньше форма молча
рапортовала об отправке, и человек ждал ссылку, которую никто не отправлял:
молчание дороже подсказки о существовании адреса, тем более что регистрация
и так отвечает 409 на занятый email. Несуществующий адрес по-прежнему получает
ровно `204` и ничего больше — перебирать адреса по-прежнему нечего.

### Часовые пояса учитываются там, где это меняет смысл данных

«Сегодня» для пользователя в UTC+3 и на сервере в UTC — разные даты, поэтому
дневная статистика, серия дней и время напоминания считаются в поясе пользователя
(`IClock.TodayFor`). Наигравшись с этим один раз, легко перестать путать
локальное время с UTC.

### Словарь собран без чужих лицензий

Примеры и переводы написаны под бытовые сценарии, а не скопированы из словарей.
Это снимает вопрос лицензий (у Wiktionary лицензия CC BY-SA с обязательной
атрибуцией, у аудио Wikimedia — тоже) и даёт лучшее качество: «снять квартиру:
deposit, lease, utilities, landlord» запоминается лучше академической фразы.
Если позже будете подключать внешние источники — атрибуция обязательна,
и место для неё уже есть (`WordExample.Attribution`).

## Запуск

Требуется .NET SDK 10 и Docker (или свой PostgreSQL).

```bash
# 1. База
docker compose up -d          # PostgreSQL на localhost:5433

# 2. Локальные секреты (файл вне репозитория)
cp appsettings.Local.example.json appsettings.Local.json   # и заполнить

# 3. Схема и словарь
dotnet run --project EnglishTrainer.Api -- migrate
dotnet run --project EnglishTrainer.Api -- seed

# 4. Сервис
dotnet run --project EnglishTrainer.Api

# 5. Бот — отдельным процессом, если он нужен
dotnet run --project EnglishTrainer.Bot
```

В режиме `Development` шаги 3 можно пропустить: `Database:AutoMigrate` и
`Database:SeedOnStartup` включены в `appsettings.Development.json`, и база
приводится в рабочее состояние при старте.

* **Тренажёр: <http://localhost:5201>** — откройте в браузере
* Документация OpenAPI: <http://localhost:5201/openapi/v1.json> (только Development)
* Состояние сервиса: <http://localhost:5201/health>

### Интерфейс тренировки

Открыв <http://localhost:5201>, вы попадаете на страницу входа. Дальше — пять разделов,
между которыми можно переключаться в боковом меню:

| Раздел | Что там |
|---|---|
| Тренировка | Сводка прогресса, незавершённая сессия, 18 колод с прогрессом, словарь колоды со звёздочками |
| Избранное | Отмеченные слова с их статусом и кнопка «Тренировать избранное» |
| Друзья | Поиск по нику, входящие и исходящие заявки, список друзей с их прогрессом |
| Настройки | Лимит новых слов, размер сессии, дневная цель, напоминание, часовой пояс |
| Профиль | Аватар, ник и отображаемое имя, привязка Telegram, дата регистрации, сводка прогресса |

Что стоит знать про его устройство:

* Это **статические файлы** в `wwwroot`: разметка, стили и двенадцать ES-модулей
  (`js/api.js`, `js/session.js`, `js/theme.js`, `js/telegram.js`, `js/pages/*.js`).
  Ни сборки, ни npm, ни отдельного процесса: интерфейс работает сразу после `dotnet run`.
* **Тёмная тема** переключается кнопкой в шапке. Режимов три — светлый, тёмный
  и «как в системе»; на `<html>` выставляется уже разрешённое значение, поэтому
  палитра описана один раз. Первая отрисовка не мигает белым: тему выставляет
  крошечный скрипт в `<head>`, который успевает раньше модулей.
* **Внутри Telegram** палитра берётся у клиента (`--tg-theme-*`), боковое меню
  превращается в нижнюю панель с вкладками, а высота окна считается по
  `viewportStableHeight` — иначе последний ряд кнопок уезжает под панель мессенджера.
* **Экран ответа в мини-аппе уплотняется.** На телефоне заголовок страницы, отступы
  карточки и кнопка «Проверить» в сумме оказывались выше окна, и до кнопки приходилось
  пролистывать на каждой карточке. Во время сессии (`body.session-active`) заголовок
  страницы скрывается, карточка и варианты ответа ужимаются, а поле ввода и «Проверить»
  остаются в одной строке — карточка помещается в окно целиком. Кнопка «Прервать»
  остаётся: кнопка «назад» есть не во всех клиентах Telegram.
* Роутинг — на хеше (`#/friends`), поэтому серверу не нужны правила перенаправления:
  любой раздел открывается по прямой ссылке. Раздел с переменной частью адреса один —
  профиль игрока (`#/user/ник`). Когда понадобится настоящий SPA
  с историей и серверным рендерингом, он встанет рядом и будет обращаться к тем же эндпоинтам.
* Интерфейс — **такой же клиент API**, как будущий Telegram-бот: он не знает
  ни про базу, ни про алгоритм повторений. Правильного ответа сервер ему не отдаёт,
  поэтому проверка всегда идёт запросом (`POST /api/study/review`).
* Токен хранится в `localStorage`. Серверных сеансов с cookie нет, поэтому
  и защита от CSRF не нужна: браузер не прикладывает токен к чужим запросам сам.
* Тренировка проходится с клавиатуры: цифры `1`–`4` выбирают вариант,
  `Enter` проверяет ответ и продолжает после разбора. Кнопка **«Не знаю»** показывает
  ответ, не заставляя угадывать, и ставит оценку «забыл».
* Активная сессия запрашивается отдельным эндпоинтом `/api/study/session/active`.
  Обычный запрос сессии создал бы новую и израсходовал дневной лимит новых слов,
  даже если человек просто открыл страницу и ушёл.

### Настройки для локального запуска

Токен бота, строка подключения к своей базе и секрет подписи токенов лежат
в `appsettings.Local.json` — файле **вне репозитория** (он в `.gitignore`).
Образец для копирования — `appsettings.Local.example.json`:

```bash
cp appsettings.Local.example.json appsettings.Local.json   # и заполнить
```

Один файл на оба процесса: его читают и API, и бот. Две копии секрета разошлись бы,
и «мини-апп открывается, а вход в нём не работает» выяснялось бы полдня. Порядок
источников: `appsettings.json` → `appsettings.Development.json` → user-secrets →
`appsettings.Local.json` → переменные окружения → командная строка. Переменные
окружения намеренно добавлены заново после файла, чтобы секреты развёртывания
оставались старше локального файла.

### Telegram: мини-апп и бот

Мини-апп — это тот же интерфейс, что и в браузере: отдельной сборки нет, а
`js/telegram.js` добавляет то, чего требует мессенджер.

**Что нужно один раз сделать в @BotFather**

1. `/newbot` — получить токен и положить его в `appsettings.Local.json`
   в `Telegram:BotToken`.
2. `/setmenubutton` — указать адрес мини-аппа (или ничего не делать: бот сам
   выставит кнопку меню методом `setChatMenuButton` при старте).
3. Имя бота без «@» записать в `Telegram:BotUsername` — из него собирается
   ссылка привязки аккаунта.

**HTTPS обязателен.** Telegram открывает мини-апп только по HTTPS, и это его
ограничение, а не кода. Локально адрес выдаёт туннель:

```bash
cloudflared tunnel --url http://localhost:5201     # или: ngrok http 5201
# полученный адрес вида https://<случайное>.trycloudflare.com
# записать в Telegram:WebAppUrl
```

Без HTTPS приложение работает как обычно: кнопка мини-аппа просто не появится,
а бот отправит сообщение без неё — в журнал уйдёт предупреждение с причиной.

**Запуск бота** — вторым процессом, рядом с API:

```bash
dotnet run --project EnglishTrainer.Api     # в одном окне
dotnet run --project EnglishTrainer.Bot     # в другом
```

Без токена бот не стартует и пишет об этом в журнал; недоступный Telegram он
переживает и повторяет попытку каждые 15 секунд.

**Отладка мини-аппа без туннеля.** Telegram открывает мини-апп только по HTTPS
и только внутри своего клиента, поэтому разрабатывать интерфейс «через Telegram»
неудобно: нужен публичный адрес, туннель и телефон. Но скрипт `telegram-web-app.js`
читает данные мини-аппа из адреса страницы — ровно так же, как их подставляет сам
Telegram. Значит, подписанную строку можно положить в адрес вручную:

```bash
dotnet run --project EnglishTrainer.Api     # в одном окне
pwsh ./scripts/telegram-dev-url.ps1         # в другом
```

Скрипт печатает ссылку вида `http://localhost:5201/#tgWebAppData=…` со свежей
подписью. Открыв её в обычном браузере, вы увидите мини-апп с темой мессенджера,
нижней панелью и **настоящим автоматическим входом по подписи**: сервер проверяет
её так же строго, как подпись от Telegram. Аккаунт привязывается тут же — кодом
из профиля на сайте.

Чего этот способ не проверяет: как мини-апп выглядит на телефоне и как ведёт себя
настоящий клиент. Всё остальное — вход, привязка, вёрстка, запросы к API — работает
по-настоящему, и правки интерфейса проверяются за секунду, без туннеля.

**Если туннель не поднимается.** Cloudflare Tunnel на некоторых каналах недоступен:
клиент не может найти свои узлы, потому что запись `argotunnel.com` и SRV-запись
`_v2-origintunneld._tcp.argotunnel.com` не отдаёт ни системный резолвер, ни 1.1.1.1
(порт 53 перехватывается провайдером). Симптом в журнале — `edge discovery: error
looking up Cloudflare edge IPs`. Это блокировка инфраструктуры, а не кода; подойдут
другие провайдеры туннелей — `ngrok`, Microsoft Dev Tunnels или `ssh -R` на
`localhost.run`, у каждого своя инфраструктура и свои домены.

**Как устроен вход в мини-апп.** Пароля там нет: Telegram передаёт странице
строку `initData`, подписанную токеном бота. Сервер проверяет подпись
HMAC-SHA256 (`TelegramInitDataValidator`), сверяет срок давности и только потом
выдаёт обычный токен доступа. Непроверенная подпись — это не «дополнительный
барьер», а единственная защита: без неё чужой идентификатор Telegram достаточно
просто отправить в запросе.

Три исхода входа намеренно различаются кодами:

| Код | Что значит | Что делает интерфейс |
|---|---|---|
| 200 | Подпись верна, Telegram привязан | Показывает тренажёр |
| 401 | Подпись неверна или устарела | Просит открыть приложение заново |
| 403 | Подпись верна, но Telegram не привязан | Показывает экран привязки, **не стирая** токен |

Разделение 401 и 403 принципиально: клиент на 401 стирает токен и показывает вход,
а «не привязан» — не истёкший сеанс, и разлогинивать человека в веб-версии из-за
этого нельзя.

**Привязка аккаунта.** Код выдаёт веб-версия в профиле; перенести его можно двумя
способами — отправить боту `/link КОД` или вставить в мини-аппе. Второй путь
существует потому, что мини-апп уже знает, какой это аккаунт Telegram: гонять
человека в чат ради того же результата — лишний шаг, а на телефоне неудобный.
Код одноразовый, живёт 15 минут, в базе хранится только его SHA-256.

**Когда приходит напоминание.** Момент следующего напоминания хранится в UTC
в `user_settings.next_reminder_at_utc` и пересчитывается при каждой правке, влияющей
на расписание: время напоминания, часовой пояс, включённость, привязка Telegram.
Планировщик раз в минуту выбирает строки по индексу на этот столбец — то есть
его стоимость не растёт вместе с числом пользователей, в отличие от перебора
«у кого локальное время совпало с настройкой».

Расписание сдвигается **до** отправки. Это осознанный размен: повторный запуск
планировщика в ту же минуту не отправит напоминание дважды, а неудачная отправка
оставит человека без одного напоминания. Два одинаковых сообщения раздражают
сильнее, чем одно недостающее, и выглядят как сломанный сервис.

**Переходы на летнее время** разобраны отдельно (`ReminderSchedule`). В ночь
перевода часов вперёд некоторых моментов не существует вовсе — наивный перевод
локального времени в UTC на них падает, и напоминание пропадает. Несуществующее
время сдвигается на час вперёд: лучше отправить позже, чем не отправить.

### Свой PostgreSQL вместо контейнера

Если PostgreSQL уже установлен, контейнер не нужен. Создайте пустую базу
(таблицы создаст `migrate`) и задайте строку подключения — она читается
из `ConnectionStrings:Postgres`:

```bash
createdb -U postgres english_trainer
export ConnectionStrings__Postgres="Host=localhost;Port=5432;Database=english_trainer;Username=postgres;Password=..."
```

Чтобы не задавать переменную окружения в каждом окне, строку удобнее положить
в секреты разработчика — они лежат вне репозитория и подхватываются
в `Development` автоматически, переопределяя `appsettings`:

```bash
cd EnglishTrainer.Api
dotnet user-secrets set "ConnectionStrings:Postgres" "Host=localhost;Port=5432;Database=english_trainer;Username=postgres;Password=..."
```

Посмотреть сохранённое: `dotnet user-secrets list`. Удалить, чтобы вернуться
к базе из `appsettings`: `dotnet user-secrets remove "ConnectionStrings:Postgres"`.

Если Docker недоступен (например, нет сети для загрузки образа), можно поднять
отдельный локальный кластер из уже установленного PostgreSQL — прямо в каталоге
проекта, не трогая системный:

```bash
initdb -D .pgdata -U postgres --auth=trust
postgres -D .pgdata -p 55432          # отдельное окно; порт не пересекается с системным
export ConnectionStrings__Postgres="Host=127.0.0.1;Port=55432;Database=english_trainer;Username=postgres"
```

Каталог `.pgdata` внесён в `.gitignore` и удаляется обычным `rm -rf`, когда
контейнер снова станет доступен.

### Секрет подписи токенов

Секрет (`Jwt:Secret`) в репозитории есть только для локального запуска.
В развёртывании он обязателен и передаётся извне — приложение **не стартует**
с пустым или коротким секретом:

```bash
export Jwt__Secret="<случайные 32+ байта>"
```

Локально его удобно держать в user-secrets:

```bash
dotnet user-secrets --project EnglishTrainer.Api set "Jwt:Secret" "<секрет>"
```

## Развёртывание на сервере

Сайт, мини-апп и бот работают на одном сервере. Поднимаются одной командой —
`docker compose -f docker-compose.prod.yml up -d --build` — и состоят из четырёх
контейнеров:

```
интернет ──► caddy :80/:443 ──► api :8080   (сайт, мини-апп, API)
                                  │
                                  ├──► postgres   (наружу не публикуется)
                                  └──► bot        (входящих портов нет вовсе)
```

### Быстрый путь

Всё то же самое одной командой с машины разработчика: скрипт копирует рабочую
копию на сервер, готовит `.env` со случайными секретами, ставит Docker, если его
нет, собирает образы и дожидается ответа приложения.

```powershell
.\scripts\deploy.ps1 -Server root@203.0.113.10 -PublicUrl https://203.0.113.10.sslip.io
```

**Если PowerShell запрещает запуск неподписанного скрипта** («файл не имеет
цифровой подписи»), есть два пути. Первый ничего не меняет в системе — скрипт
запускается своим содержимым, и политика выполнения к такому запуску не
применяется:

```powershell
& ([scriptblock]::Create((Get-Content .\scripts\deploy.ps1 -Raw))) `
    -Server root@203.0.113.10 -PublicUrl https://203.0.113.10.sslip.io
```

Второй ослабляет политику **только для текущего окна** (закрыли окно — настройка
исчезла, в реестр ничего не пишется):

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\deploy.ps1 -Server root@203.0.113.10 -PublicUrl https://203.0.113.10.sslip.io
```

Файл скрипта сохраняется в UTF-8 **с BOM**: без него Windows PowerShell 5.1
читает его как ANSI, и «ё» в комментариях превращается в кавычку, разрывающую
строки. Редакторы, снимающие BOM, ломают запуск — проверяйте первые три байта
(`EF BB BF`), как и у `smoke-test.ps1`.

**Это же и обновление прода.** Скрипт идемпотентен: повторный запуск с теми же
параметрами выкладывает текущую рабочую копию, применяет новые миграции (их
выполняет отдельный сервис `migrate` до старта `api`) и перезапускает контейнеры.
Существующий `.env` при этом сохраняется — иначе сменившийся пароль базы сломал бы
подключение к уже созданной базе.

Что скрипт переносит в `.env` сервера при каждом запуске:

| Что | Откуда берётся |
|---|---|
| `PUBLIC_URL`, `HTTPS_PORT` | Параметры `-PublicUrl` и `-HttpsPort` |
| Токен бота и имя бота | `appsettings.Local.json` (`Telegram`) |
| Пароль базы, секрет токенов | Из существующего `.env` (или создаются случайными при первом развёртывании) |
| Настройки почты `EMAIL_*` | `appsettings.Local.json` (`Email`) |

Настройки почты переносятся вместе с кодом, потому что «настроил локально,
а на сервере забыл» — типовая поломка, и выглядит она как «почта настроена,
а письма не приходят». Если в `appsettings.Local.json` почта не заполнена,
скрипт так и скажет: письмо со ссылкой для сброса пароля будет выводиться
в журнал контейнера `api`.

В конце скрипт печатает строку, которую `api` записал о почте при запуске, —
по ней сразу видно, уходит письмо или остаётся в журнале:

```
== Почта на сервере
   Почта: smtp.mail.ru:587, отправитель you@mail.ru.
```

Проверка боем: открыть сайт, «Забыли пароль?», ввести свою почту — письмо должно
прийти. Если его нет, причина будет в журнале:

```powershell
ssh root@203.0.113.10 "cd /opt/english-trainer && docker compose -f docker-compose.prod.yml logs --tail 50 api"
```

Что стоит знать про почту на сервере:

* **Нужен исходящий порт 587.** Порт 25 у большинства хостингов закрыт, но 587 для
  отправки по STARTTLS открыт почти везде: им пользуются все почтовые клиенты.

  Проверить, не блокирует ли хостинг почтовые порты, можно прямо с сервера:

  ```bash
  timeout 8 bash -c 'exec 3<>/dev/tcp/smtp.mail.ru/587' && echo открыт || echo закрыт
  timeout 8 bash -c 'exec 3<>/dev/tcp/portquiz.net/587' && echo открыт || echo закрыт
  ```

  `portquiz.net` принимает соединения на любом порту: если он молчит, закрыт
  именно исходящий порт, а не почтовый сервер.

* **Если порты закрыты — отправляем через HTTP API.** Обойти блокировку нельзя
  (это антиспам-политика провайдера), но HTTPS открыт всегда, поэтому письмо
  уходит обычным POST-ом. Подключение Brevo — бесплатно 300 писем в день:

  1. Зарегистрироваться на <https://brevo.com> и подтвердить адрес отправителя:
     **Senders** → добавить свой адрес → Brevo пришлёт на него письмо со ссылкой.
     Без подтверждения отправлять с этого адреса нельзя.
  2. Создать ключ: **SMTP & API** → **API Keys** (вид `xkeysib-…`).
  3. В `appsettings.Local.json` поставить `"Provider": "brevo"` и вписать ключ
     в `"Brevo": { "ApiKey": "xkeysib-…" }`.
  4. Запустить `scripts/deploy.ps1` — ключ уедет в `.env` сервера, а в журнале
     появится строка `Почта: Brevo (HTTP API), отправитель …`.

  Отказ сервиса обрабатывается так же, как отказ SMTP: причина в журнале, письмо
  целиком в журнале (ссылка не пропадает), форма показывает ошибку вместо
  обещания «письмо отправлено».

* **Ждать долго не придётся.** `Email:TimeoutSeconds` (по умолчанию 20) — сколько
  ждать почтовый сервис. Умолчание `SmtpClient` в сто секунд превращало
  заблокированный порт в двухминутное ожидание на форме восстановления пароля.
* **Ссылка в письме ведёт на `PUBLIC_URL`.** Он подставляется в `Email__PublicUrl`,
  поэтому ссылка не указывает на внутренний адрес контейнера. Если её всё же
  приходится задавать руками, это `Email:PublicUrl` в `.env`.
* **Пароль — «пароль для внешнего приложения».** Mail.ru, Яндекс и Gmail не
  принимают пароль от ящика. Если пароль сменят, в `.env` на сервере останется
  старый, и отправка начнёт падать с «Authentication failed» — `deploy.ps1`
  обновляет этот ключ из `appsettings.Local.json` при каждом запуске.
* **Письмо не потеряется.** Если почтовый сервер отказал, ссылка всё равно уходит
  в журнал `api`, а форма покажет ошибку вместо обещания «письмо отправлено».
  Проверить: `docker compose -f docker-compose.prod.yml logs api | grep -A6 'Письмо'`.


Скрипт идемпотентен: повторный запуск обновляет приложение. `.env` он сохраняет
в рабочей копии (файл в `.gitignore`) и при следующих запусках берёт существующий —
это принципиально, потому что **смена пароля в `.env` не меняет пароль уже
созданной базы**: приложение просто перестало бы к ней подключаться.

Чего скрипт не делает: не выдаёт сертификат за вас (это Caddy, ему нужен домен,
указывающий на сервер) и не проверяет, доступен ли IP сервера из вашей сети.
Второе стоит проверить заранее — с телефона, по мобильному интернету.

### Что нужно

* Сервер на Linux с Docker (проверить: `docker --version`). Если его нет —
  `curl -fsSL https://get.docker.com | sh`.
* Открытые порты 80 и 443: Caddy получает сертификат Let's Encrypt сам,
  а для проверки владения доменом ему нужен 80-й.
* **Домен, указывающий A-записью на IP сервера.** Домена нет — возьмите
  `sslip.io`: он резолвит любой вписанный в имя IP, и Let's Encrypt выдаёт
  на такое имя настоящий сертификат. Для сервера `203.0.113.10` это
  `https://203.0.113.10.sslip.io`.

### Шаги

```bash
# 1. Код на сервере
git clone <адрес репозитория> && cd EnglishTrainer

# 2. Настройки: в .env попадают пароль базы, секрет токенов и токен бота
cp .env.example .env
nano .env

# 3. Сборка и запуск
docker compose -f docker-compose.prod.yml up -d --build

# 4. Проверка
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f api
```

Дальше: открыть `PUBLIC_URL` в браузере и зарегистрироваться. Мини-апп бот
подключит сам — при старте он ставит кнопку меню на адрес из `Telegram__WebAppUrl`
(в журнале будет строка «Кнопка меню ведёт на …»). Туннель вроде ngrok больше
не нужен: адрес публичный.

**Кнопка меню — общая на весь бот, и локальный запуск её перебивает.** Токен бота
один и тот же в разработке и на сервере, поэтому бот, запущенный на своей машине,
ставит кнопку на локальный туннель (`Telegram:WebAppUrl` из `appsettings.Local.json`).
Телефон после этого открывает не сервер, а ваш компьютер — а если туннель уже
закрыт, мини-апп показывает страницу-заглушку ngrok, и выглядит это как «на сервере
ничего не обновилось». Лечится перезапуском бота на сервере или одной командой:

```bash
TOKEN=$(docker compose -f docker-compose.prod.yml exec -T api printenv Telegram__BotToken)
curl -s -X POST "https://api.telegram.org/bot$TOKEN/setChatMenuButton" \
  -H 'Content-Type: application/json' \
  -d '{"menu_button":{"type":"web_app","text":"Тренажёр","web_app":{"url":"'$PUBLIC_URL'/"}}}'
```

**У кнопки меню есть пауза между изменениями.** Telegram отвечает `ok: true`,
но применяет адрес не сразу: частые вызовы подряд (например, при отладке) молча
игнорируются, и `getChatMenuButton` продолжает показывать прежний адрес. Если
кажется, что адрес «не принимается», подождите несколько минут и позовите один
раз — проверено на живом боте: адрес сервера встаёт нормально, а отвергался он
только из-за частоты вызовов.

### Почему сделано именно так

**Наружу смотрит только Caddy.** Порт API не публикуется, база тоже. Это не
аккуратность, а условие безопасности: приложение доверяет заголовкам
`X-Forwarded-*` (иначе ссылка для сброса пароля указывала бы на внутренний адрес,
а перенаправление на HTTPS зацикливалось бы). Если порт API открыть наружу,
любой желающий сможет подставить себе любую схему и адрес.

**Миграции — отдельный шаг, а не «при старте».** Сервис `migrate` применяет схему
и загружает словарь до запуска приложения; `api` и `bot` ждут его завершения.
При нескольких экземплярах одновременное применение миграций — это гонка.

**Секретов в образе нет.** `.env` в `.gitignore`, `appsettings.Local.json`
в `.dockerignore`. Всё, что нужно приложению, приходит переменными окружения —
это единственный способ хранить секреты, который не требует следить за файлами.

**Тома для того, что должно пережить обновление:** база, аватары пользователей
и сертификаты Let's Encrypt. Без последнего Caddy запрашивал бы новый сертификат
после каждого пересоздания контейнера, а у Let's Encrypt есть недельный лимит.

### Восстановление доступа

Пароль можно вернуть двумя способами.

**Через интерфейс.** На экране входа есть ссылка «Забыли пароль?»: введите email или ник,
и сервис отправит ссылку для сброса. Как именно — зависит от настроек:

| Что задано | Куда уходит письмо |
|---|---|
| `Email:Smtp:Host` и `Email:From` | На почту получателя по SMTP |
| Ничего | В **журнал сервера**: откройте окно, где запущен API, и скопируйте ссылку вида `http://localhost:5201/#/reset?token=…` |

Способ доставки интерфейс спрашивает у сервера (`GET /api/auth/password-reset-method`),
поэтому форма не отправляет человека проверять почту, которой он не получит. Ссылка
действует два часа и срабатывает один раз.

Почему журнал — рабочий режим, а не заглушка: приложение рассчитано и на запуск для
себя, где почтового провайдера нет. Порт `IEmailSender` объявлен в `Domain`,
реализаций две — `SmtpEmailSender` и `LogEmailSender`, и выбор идёт по настройкам,
а не по режиму сборки: одна и та же сборка отправляет письма на сервере и пишет
их в журнал на ноутбуке.

Настройка почты (локально — в `appsettings.Local.json`, в развёртывании — в `.env`):

```jsonc
"Email": {
  "Smtp": {
    "Host": "smtp.mail.ru",
    "Port": 587,                       // не 465 — см. ниже
    "User": "you@mail.ru",             // адрес берётся из настроек Mail.ru
    "Password": "пароль для внешнего приложения",
    "EnableSsl": true
  },
  "From": "you@mail.ru",
  "FromName": "EnglishTrainer",
  "PublicUrl": "https://trainer.example.com"
}
```

**Почему 587, а не 465.** На 465 шифрование начинается с первого байта (implicit
SSL), и `System.Net.Mail.SmtpClient` этого не умеет: он поддерживает только STARTTLS,
когда сервер сам предлагает перейти на шифрование. `smtp.mail.ru:587` STARTTLS
объявляет (проверено), поэтому пара «587 + `EnableSsl`» работает, а на 465 соединение
просто не состоится. Добавлять ради этого почтовую библиотеку вроде MailKit не
пришлось: письмо в приложении одно.

**Пароль — не пароль от ящика.** Mail.ru (как Яндекс и Gmail) требует «пароль для
внешнего приложения»: он выдаётся в настройках безопасности и отзывается отдельно
от основного. Пароль от почтового ящика сервер отклонит.

`PublicUrl` нужен за обратным прокси: внутренний адрес контейнера в письме бесполезен,
а внешний по запросу определяется не всегда. В развёртывании те же значения приходят
переменными `Email__Smtp__Host`, `Email__Smtp__User`, `Email__Smtp__Password`,
`Email__From` и так далее — образец в `.env.example`.

**Из командной строки.** Если войти не удаётся вообще (например, забыт и пароль,
и почта), пароль задаётся напрямую — команда выше. Она просит пароль дважды, чтобы
опечатка не закрыла аккаунт повторно.

Что стоит знать про безопасность этой части:

* В базе хранится только **SHA-256 от токена** сброса, а не сам токен: утечка таблицы
  не даёт возможности сбросить чужой пароль.
* Форма «забыли пароль» отвечает `204` на **несуществующий** адрес — перебирать
  адреса по ней нечего, в отличие от регистрации: та честно отвечает `409`
  на занятый email. Отправка письма существующему пользователю — единственный
  случай, когда ответ отличается (`502`, если почта отказала), и это сознательный
  размен: молчаливая «отправка» в никуда стоит дороже.
* Смена пароля требует текущий пароль, даже если токен доступа уже есть: иначе
  украденный токен превращался бы в полный захват аккаунта.
* Уже выданные токены доступа после смены пароля **продолжают действовать** — JWT
  проверяется подписью, и отозвать его без списка отозванных токенов нельзя. Для
  этого приложения риск принят осознанно; если понадобится, добавим хранилище `jti`.

## Модель данных

**Общий справочник:** `words`, `word_translations`, `word_examples`, `decks`, `deck_words`.

**Личные данные:** `users`, `user_settings`, `card_states`, `review_logs`,
`study_sessions`, `study_session_items`, `daily_stats`, `favorite_words`, `friendships`,
`password_reset_tokens`, `telegram_link_codes`, `user_achievements`.

Колоды лежат в общем справочнике, но личные отмечены владельцем:
`decks.owner_id` пуст у системных и заполнен у созданных пользователем. Отдельной
таблицы для личных колод нет — это те же колоды, и все механизмы обучения
работают с ними одинаково.

Аватары в базе не хранятся: там лежит только имя файла (`users.avatar_file_name`).
Изображения — не место в таблице пользователей: они раздувают строку, попадают
во все выборки и мешают резервному копированию. Файлы лежат в `wwwroot/avatars`,
имя генерирует сервер (GUID), поэтому подделать путь или перезаписать чужой
файл нельзя, а смена аватара автоматически сбрасывает кеш браузера.

Индексы, которые нужны с первого дня и уже созданы:

| Индекс | Зачем |
|---|---|
| `card_states (UserId, WordId)` уникальный | Одно состояние на пару «пользователь + слово»: защита от дублей при гонках |
| `card_states (UserId, DueAt)` | Самый горячий запрос: «что пора повторить» |
| `review_logs (UserId, ReviewedAt)` | Кривая удержания |
| `review_logs (CardStateId, ReviewedAt)` | История по конкретному слову |
| `ix_study_sessions_active_per_user` частичный уникальный | Только одна активная сессия на пользователя |
| `daily_stats (UserId, Date)` уникальный | Дневные агрегаты без дублей |
| `words (Lemma, PartOfSpeech)` уникальный | `work` как глагол и как существительное — разные слова |
| `users (Username)` уникальный | Ник — адрес, по которому пользователя находят друзья |
| `favorite_words (UserId, WordId)` уникальный | Слово нельзя отметить избранным дважды |
| `friendships (RequesterId, AddresseeId)` уникальный | Повторная заявка от того же человека невозможна |
| `users (TelegramId)` уникальный, с фильтром `IS NOT NULL` | Один Telegram — один аккаунт: иначе непонятно, чей прогресс показывать в мини-аппе |
| `telegram_link_codes (CodeHash)` уникальный | Поиск кода идёт строго по хешу; совпадение хешей означало бы общую ссылку |
| `user_settings (NextReminderAtUtc)` | Планировщик просыпается раз в минуту: без индекса он читал бы таблицу целиком |
| `user_achievements (UserId, Code)` уникальный | Награда выдаётся один раз; проверка идёт после каждого открытия страницы, и два одновременных запроса без индекса выдали бы её дважды |

Именование единое: таблицы и столбцы — в `snake_case`, поэтому запросы вручную
не требуют кавычек (`select due_at from card_states`). Правило задано конвенцией
[SnakeCaseNamingConvention.cs](EnglishTrainer.Infrastructure/Persistence/Conventions/SnakeCaseNamingConvention.cs),
а не перечислением столбцов: оно автоматически распространится на новые сущности.

Миграции: [InitialCreate](EnglishTrainer.Infrastructure/Migrations/20261010120727_InitialCreate.cs)
(схема целиком), [AddFavoritesAndFriends](EnglishTrainer.Infrastructure/Migrations/20261010124428_AddFavoritesAndFriends.cs)
(ник, избранное, друзья), [AddPasswordResetTokens](EnglishTrainer.Infrastructure/Migrations/20261010133110_AddPasswordResetTokens.cs),
[AddUserAvatar](EnglishTrainer.Infrastructure/Migrations/20261011090000_AddUserAvatar.cs),
[AddTelegramLinkCodes](EnglishTrainer.Infrastructure/Migrations/20261011091500_AddTelegramLinkCodes.cs) и
[AddUserAchievements](EnglishTrainer.Infrastructure/Migrations/20261011093000_AddUserAchievements.cs) и
[AddOwnDecks](EnglishTrainer.Infrastructure/Migrations/20261011094500_AddOwnDecks.cs).
Вторая — пример того, как добавить обязательный столбец в таблицу, где уже есть данные:
сначала колонка появляется необязательной, затем заполняется из email с разведением
совпадений, и только потом становится обязательной и уникальной. Одним действием
существующие строки стали бы невалидными.

Снапшот модели лежит рядом с миграциями — он нужен для будущих `dotnet ef migrations add`.

### Если `dotnet ef` недоступен

Инструмент `dotnet-ef` ставится из nuget.org, а в окружении без сети это невозможно.
На такой случай в репозитории есть `scripts/ef-add-migration.ps1`: он собирает файл
снимка модели (`<Имя>.Designer.cs`) из `AppDbContextModelSnapshot.cs` — тела у них
совпадают строка в строку — и создаёт каркас миграции, в который остаётся вписать
`Up` и `Down`.

```bash
powershell -ExecutionPolicy Bypass -File ./scripts/ef-add-migration.ps1 -Name AddSomething
```

Порядок такой: сначала правится модель и снапшот (он описывает состояние **после**
миграции), затем запускается скрипт, затем заполняются `Up` и `Down`. Незаполненная
миграция намеренно бросает исключение: пустая миграция опаснее падения — схема
молча остаётся старой.

## Тесты

```bash
dotnet test
```

227 тестов: алгоритм интервалов (рост интервалов, провалы, границы), нормализация
ответов, правила ника (длина, допустимые символы, вывод ника из email, разведение
совпадений), подсчёт серии дней (пропуски, «сегодня ещё не занимался», длиннейшая
серия), хеширование паролей, приёмка и отказ токенов (включая `alg=none`, чужой
ключ, подменённую нагрузку), контракт карточки.

Отдельно про шесть наборов, добавленных позже:

* **Правила приёма аватара.** Пустой файл, превышение размера, файл, только
  притворяющийся картинкой (SVG со скриптом, PHP, GIF), границы «ровно предел»
  и «на байт больше», а также случай, когда клиент соврал в размере. Здесь
  проверяется не косметика, а граница безопасности: каталог аватаров раздаётся
  статикой, и всё, что прошло проверку, становится доступно по прямой ссылке.
* **Подпись данных мини-аппа.** Верная подпись, подпись чужим токеном,
  подменённое поле, истёкший и «будущий» `auth_date`, регистр hex, поле
  `signature` из Bot API 8.0. Это единственная защита входа в мини-апп: пароля
  там нет, и без проверки подписи чужой идентификатор Telegram достаточно
  просто отправить в запросе.
* **Момент напоминания.** Часовые пояса в обе стороны от UTC, переход на летнее
  время в обе стороны, неизвестный пояс. В ночь перевода часов вперёд некоторых
  моментов не существует, и наивный перевод локального времени в UTC на них падает.
* **Контракт карточки.** Отдельно закреплено, что в заданиях на ввод и написание
  правильного ответа нет ни в одном поле, включая текст для произношения,
  и что в упражнении на слух этот текст есть и совпадает с ответом.
* **Каталог достижений.** Уникальность кодов, положительные пороги, покрытие
  показателей, границы «ровно порог» и «на единицу меньше», обрезка прогресса,
  и главное — что незапрошенный показатель читается как ноль. На последнем
  держится обещание «достижение не выдаётся ошибочно, если его не считали».
* **Рейтинг.** Границы недельного окна (день за его пределами не считается),
  серия по всей истории, а не по семи дням, порядок трёх ключей сортировки,
  независимость результата от порядка строк в базе и соревновательное
  ранжирование: одинаковый счёт — одинаковое место, следующее пропускается.
* **Правила своих слов и колод.** Название, перевод, часть речи: границы длины,
  обрезка пробелов, пустые значения, часть речи вне закрытого списка. Отдельно —
  согласованность политики с самой собой (значение из списка обязано проходить
  собственную проверку) и правило владения: системную колоду не правит никто,
  чужую — тем более, а ничья несистемная не правит никто и подавно.

### Интеграционные тесты: репозитории на настоящем PostgreSQL

Сквозной сценарий проверяет API целиком, но до частных случаев он не дотягивается:
сортировки просроченных карточек, границ выборки, переиспользования слов, поведения
уникальных индексов. А EF-запрос — это код, который компилируется всегда, а работает
не всегда: неверно составленный LINQ падает не при сборке, а при первом выполнении,
и не в тесте, а у пользователя.

`tests/EnglishTrainer.IntegrationTests` поднимает настоящую базу и проверяет
репозитории напрямую — 52 теста по состояниям карточек, словарю, колодам,
достижениям, пользователям и дневной статистике.

```bash
export ConnectionStrings__Postgres="Host=localhost;Port=5433;Database=english_trainer;Username=postgres;Password=postgres"
dotnet run --project tests/EnglishTrainer.IntegrationTests
```

**Тестовая база отдельная.** Имя берётся из строки подключения, к нему дописывается
`_tests`, и база создаётся сама, если её нет. Интеграционные тесты вставляют
и удаляют строки, и делать это в базе с настоящим прогрессом нельзя. Имя проверяется
на допустимые символы: оно попадает в `create database`, где параметров не бывает.

**Каждый тест живёт в транзакции, которая откатывается.** Убирать за собой вручную —
значит помнить о каждой таблице и о порядке удаления из-за внешних ключей; одна
забытая строка, и следующий тест падает по причине, которой в его коде нет.
После прогона тестовая база пуста — это проверено, а не предположено.

**Без базы тесты не пропускаются, а падают** с текстом, что именно нужно задать.
Пропуск, заканчивающийся успехом, опаснее падения: «все тесты пройдены» на машине,
где не выполнился ни один, — это ложная уверенность.

### Непрерывная интеграция

`.github/workflows/ci.yml` выполняет на каждый push и pull request: сборку,
модульные тесты, интеграционные тесты на PostgreSQL из сервисного контейнера,
применение миграций, импорт словаря и сквозную проверку API с запущенным сервером.

Порядок шагов не случаен: сначала сборка — быстро и без базы, потом тесты,
потом сквозной сценарий. Если упало на первом шаге, разбираться в базе не нужно.
Прогон предыдущей ревизии на той же ветке отменяется: проверять устаревший коммит
бессмысленно. При сбое шага запуска в журнал выводится вывод API — без него
«сервер не поднялся» неотличимо от «сервер поднялся и упал на первом запросе».

### Если `dotnet test` не запускается

Тестовый хост VSTest при старте открывает handle родительского процесса. В окружениях,
где доступ к процессам ограничен, он падает с «Отказано в доступе», не дойдя
до тестов. На этот случай в проекте есть автономный раннер, который выполняет
**те же самые тесты и проверки** в текущем процессе:

```bash
dotnet run --project tests/EnglishTrainer.UnitTests          # модульные
dotnet run --project tests/EnglishTrainer.IntegrationTests   # интеграционные, нужна база
```

Раннер живёт отдельной библиотекой `tests/EnglishTrainer.TestRunner`, потому что
тестовых проектов два: копия на 150 строк разошлась бы при первой же правке —
например, когда один проект научился бы работать с фикстурами, а второй нет.

идемпотентность повторной проверки), рейтинг недели (одна строка без друзей,
участие друга после принятия заявки, подсчёт ответов, длина окна, возрастание мест,
закрытость от анонимных запросов), свои колоды и слова (пустое название, создание,
видимость в списке, новое слово и его поиск в общем словаре, повторное добавление,
часть речи вне списка, слово без перевода, запрос без слова, добавление существующего
слова, удаление слова, запрет правки системной и чужой колоды, удаление колоды
и сохранность слова после него), прерывание сессии.
Дополнительно проверяется контракт карточки: в задании на ввод текста для
произношения нет — иначе браузер озвучил бы ответ вслух до попытки.

Раздел проверок Telegram требует токена бота: он берётся из переменной окружения
`Telegram__BotToken` или из `appsettings.Local.json`. Без токена раздел
**пропускается** с явным сообщением — подпись `initData` иначе проверить нечем.
Строка `initData` для проверки собирается тем же алгоритмом, что использует
Telegram: пары через амперсанд, подпись — HMAC-SHA256 по строке из тех же пар
через перевод строки. Это единственный способ проверить алгоритм без настоящего
клиента.

Скрипт совместим с Windows PowerShell 5.1 (в нём нет `-SkipHttpErrorCheck`,
а строковое тело запроса искажает кириллицу — поэтому тело отправляется байтами,
а файл аватара — через `System.Net.Http`, потому что `-Form` появился только
в PowerShell 6).

**Чего сквозная проверка не покрывает.** Упражнение «на слух»: чтобы оно попалось
в очередь, карточка должна быть в фазе повторения с наступившим сроком, а этого
за один прогон не добиться — интервалы специально разносят повторения во времени.
Контракт карточки для этого упражнения закреплён юнит-тестом, а на живой базе
он проверялся руками: карточка переводилась в фазу повторения запросом к базе.
Слышимость самой озвучки проверяется только браузером — синтез речи серверу
недоступен по определению.

| 5 | Уведомление о новой награде в Telegram | Достижения уже выдаются и датируются, но бот о них не сообщает — а сообщение в чате и есть та самая минута, ради которой всё делалось |

Сознательно не сделано сейчас: отдельного воркера для фоновых задач. Планировщик
напоминаний живёт в процессе бота, и выносить его раньше, чем появится вторая
фоновая задача, — преждевременно.

## Замечания по окружению

**Сборка без доступа к сети.** В `Directory.Build.props` отключён аудит уязвимостей
NuGet (`NuGetAudit=false`): он обращается к nuget.org и при отсутствии сети
возвращает `NU1900`, что вместе с `TreatWarningsAsErrors` ломает `restore`.
При работе с сетью верните `true`.

Если сети нет и восстановление пакетов всё равно падает (`NU1301`), укажите
существующий кеш пакетов переменной окружения — путь к чужому профилю
в `nuget.config` не записан намеренно, потому что на другой машине он бесполезен:

```bash
export NUGET_PACKAGES="$HOME/.nuget/packages"
```

**`DOTNET_CLI_HOME` уводит кеш NuGet.** Если он задан (например, чтобы не мусорить
в профиле пользователя), глобальная папка пакетов переезжает в `$DOTNET_CLI_HOME/.nuget/packages`
и оказывается пустой — `restore` уходит в сеть и падает с `NU1301`. Лечится
одновременным указанием кеша:

```bash
export DOTNET_CLI_HOME="$PWD/.dotnet-home"
export NUGET_PACKAGES="$HOME/.nuget/packages"
```

**Многопроцессная сборка в ограниченном окружении.** Если `dotnet build` падает
без сообщений об ошибках (в диагностике — `MSB4276`, отказ резолверу ворклоадов),
соберите в один процесс:

```bash
dotnet build -m:1 -nodeReuse:false
```

**Запущенный API блокирует пересборку.** `dotnet build` не сможет заменить
`EnglishTrainer.Api.dll`, пока приложение работает: файл занят процессом. Остановите
сервер и соберите заново — ошибка выглядит как `MSB3021` с текстом «The process
cannot access the file».

**Скрипты PowerShell и BOM.** `scripts/smoke-test.ps1` обязан оставаться в UTF-8
**с BOM**. Без BOM Windows PowerShell 5.1 читает файл как ANSI, кириллица
превращается в мусор, и скрипт падает на разборе. Редакторы и утилиты, снимающие
BOM, ломают запуск молча: проверяйте первые три байта (`EF BB BF`).

**Логирование только в консоль.** Провайдеры заданы явно в `Program.cs`. Приёмник
Event Log по умолчанию пишет в системный журнал Windows, и без прав на запись
попытка залогировать ошибку сама становится исключением — приложение падает вместо
записи в лог.
