# Видимость в поиске: что сделано и что нажать

Документ описывает две вещи: что уже работает в коде и какую последовательность
действий нужно пройти в панелях Яндекса и Google. Код без регистрации сайта
в панелях бесполезен, а регистрация без кода — тоже, поэтому порядок важен.

## 1. Что уже отдаёт приложение

| Адрес | Что это | Кому |
|---|---|---|
| `/decks` | Оглавление каталога: 18 тем, у каждой ссылка | Люди из поиска, роботы |
| `/decks/{slug}` | Страница темы: все слова с переводом, транскрипцией и примером | Люди из поиска, роботы |
| `/sitemap.xml` | Карта сайта: главная, каталог и все темы | Роботы |
| `/robots.txt` | Правила обхода и ссылка на карту | Роботы |
| `/seo.js` | Загрузчик Метрики, номер счётчика из настроек | Все страницы |
| `/{имя}.html` | Файл подтверждения прав | Вебмастер и Search Console |

Страницы каталога собираются на сервере: текст слов лежит в HTML, а не
появляется после выполнения скрипта. Это и есть то, чего не хватало раньше —
поисковик видел пустую оболочку.

Разделы приложения (`/study`, `/friends`, `/profile` и остальные) отвечают
заголовком `X-Robots-Tag: noindex`: они за входом, и в выдаче им делать нечего.
Несуществующая тема отвечает честным `404`, а не главной страницей.

Адреса разделов теперь обычные (`/friends`, а не `/#/friends`). Старые ссылки
с хешем продолжают работать: интерфейс переписывает их в новый вид на входе.

## 2. Яндекс.Метрика

1. Откройте [metrika.yandex.ru](https://metrika.yandex.ru) → **Добавить счётчик**.
2. Название — любое («EnglishTrainer»), адрес сайта — `englishrainer.site`,
   часовой пояс — тот, в котором вам удобно смотреть отчёты.
3. **Вебвизор** — снимите галочку, если политики обработки данных на сайте ещё
   нет. Панель от этого не сломается, а запись сессий без согласия и пункта
   в политике — это персональные данные без основания. Важно: галочка в панели
   записи не включает, её включает параметр в коде. Он выключен по умолчанию
   и включается одной переменной:

   ```
   SEO_METRIKA_WEBVISOR=true
   ```

4. **Номер счётчика** (девять цифр) в проекте уже задан значением по умолчанию
   в `docker-compose.prod.yml` — `113772679`. Менять ничего не нужно, если
   счётчик один. Другой номер (например, тестовый) задаётся в `.env`:

   ```
   SEO_METRIKA_ID=12345678
   ```

5. Разверните и проверьте: `https://englishrainer.site/seo.js` должен содержать
   `ym(113772679, 'init', ...)`. Если в файле только комментарий «не настроен»,
   номер не дошёл до приложения — смотрите `Seo__YandexMetrikaId` в окружении
   контейнера.

Просмотры внутри приложения считаются отдельно: адрес меняется без перезагрузки,
поэтому роутер сам сообщает Метрике о каждом разделе (`__seoHit` в `app.js`).
Без этого все разделы попали бы в отчёт одной страницей.

## 3. Яндекс.Вебмастер

Яндекс занимает около 70% поисковых запросов в России, поэтому начинать
с него, а не с Google.

1. Откройте [webmaster.yandex.ru](https://webmaster.yandex.ru) → **Добавить сайт**.
2. Укажите `https://englishrainer.site`.
3. Выберите способ подтверждения **HTML-файл**. Панель покажет имя вида
   `yandex_<новый-токен>.html` и код вида `Verification: <новый-токен>`.
   Скачивать и загружать файл не нужно — приложение отдаёт его само, причём
   с дословно тем содержимым, которое просит Вебмастер.
4. Впишите выданное имя в `appsettings.json` (`Seo:YandexVerificationFile`)
   или задайте переменной окружения:

   ```
   SEO_YANDEX_VERIFICATION_FILE=yandex_<новый-токен>.html
   ```

   Токен привязан к домену: после переезда с прежнего адреса старый файл
   для нового домена не действует, поэтому имя в настройках сейчас пустое.
5. Разверните, убедитесь, что `https://englishrainer.site/<имя>.html`
   открывается и в теле видно `Verification: <токен>`, затем нажмите
   **Проверить** в панели.
6. После подтверждения: **Индексирование → Файлы Sitemap → Добавить** и укажите
   `https://englishrainer.site/sitemap.xml`.

Файл нужно оставить на сайте навсегда: Вебмастер перепроверяет права
периодически, и удаление файла однажды снимет подтверждение.

## 4. Google Search Console

1. Откройте [search.google.com/search-console](https://search.google.com/search-console)
   → **Добавить ресурс** → «Префикс URL» → `https://englishrainer.site`.
2. Способ подтверждения — **HTML-файл**. Имя будет вида
   `google1a2b3c4d5e6f7890.html`.

   ```
   SEO_GOOGLE_VERIFICATION_FILE=google1a2b3c4d5e6f7890.html
   ```

3. Разверните, проверьте адрес файла и нажмите **Подтвердить**.
4. **Файлы Sitemap → Добавить новую карту** → `sitemap.xml`.

## 5. Проверка после развёртывания

```bash
curl -sS https://englishrainer.site/robots.txt
curl -sS https://englishrainer.site/sitemap.xml | head -20
curl -sSI https://englishrainer.site/decks | head -5
curl -sS https://englishrainer.site/seo.js | head -5
```

Ожидается: в карте 20 адресов (главная, каталог и 18 тем), `/decks` отвечает
`200` с `text/html`, `/seo.js` содержит номер счётчика, а не заглушку.

Проверить, что старая ссылка с хешем жива: откройте
`https://englishrainer.site/#/friends` — адрес должен сам превратиться
в `/friends`.

## 6. Что делать в первые месяцы

1. **Не ждать индексации мгновенно.** Первые страницы появляются в выдаче
   через 1–3 недели, устойчивые позиции по длинному хвосту — через 3–6 месяцев.
2. **Смотреть «Страницы в поиске»** в Вебмастере: сколько в индексе, что
   исключено и почему. Если страницы не индексируются, причина обычно
   в одном из двух: мало текста или дубли адресов.
3. **Добавлять темы по одной.** Новая колода в словаре автоматически получает
   страницу и попадает в карту сайта — отдельной работы не нужно.
4. **Не покупать ссылки и не плодить страницы-пустышки.** Яндекс режет
   «малополезные страницы», и восстановление позиций после этого дороже,
   чем весь органический трафик.

## 7. Переезд на новый домен

Сайт переехал с `englishtrainer.site` на **`englishrainer.site`** (прежний адрес
был куплен с опечаткой и истёк). В коде и конфигах домен заменён, сертификаты
Caddy выпускает заново, DNS у регистратора уже указывает на сервер.

Что после переезда нужно сделать руками — это не код:

| Где | Что сделать |
|---|---|
| **Яндекс.Метрика** | В настройках счётчика добавить `englishrainer.site` в список разрешённых адресов. Пока там только старый домен, а приём данных включён «только с указанных адресов» — статистики не будет |
| **Яндекс.Вебмастер** | Добавить новый сайт, получить **новое** имя файла подтверждения, прислать его — оно вписывается в `Seo:YandexVerificationFile` |
| **Google Search Console** | То же самое: новый ресурс и новый файл `google….html` |
| **Telegram** | Бот при старте ставит кнопку меню на адрес из `Telegram__WebAppUrl`, то есть на новый домен — достаточно перезапуска. Если адрес задавался вручную в BotFather, обновите и там |
| **VPN-клиенты** | Поддомен сменился: `cdn.englishtrainer.site` → `cdn.englishrainer.site`. Готовые конфиги у клиентов содержат старый адрес — их нужно переимпортировать заново из панели 3x-ui |

Что переезжает само, без действий:

- `sitemap.xml`, `robots.txt`, `canonical` и разметка schema.org — собираются из
  `Seo:PublicBaseUrl`, он уже новый;
- ссылки в письмах (сброс пароля) — из `Email:PublicUrl` = `PUBLIC_URL`;
- сертификаты — Caddy выпустит при первом обращении к новому домену.

**Индексация начнётся заново.** Для Яндекса новый домен — новый сайт: прежние
позиции и история не переносятся, первые страницы появятся через 1–3 недели
после подтверждения прав и загрузки карты сайта.
